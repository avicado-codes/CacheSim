# ccsim web

The ccsim website: React 18 + TypeScript + Vite, Zustand for state, Apache ECharts for charts
([ARCHITECTURE](../docs/ARCHITECTURE.md) section 15). The C++ engine runs in a Web Worker as
WebAssembly. **The frontend never simulates.** Every number, grid state and narration step comes
from the engine's events, snapshots and JSON reports.

## Layout

| Path | What it is |
|---|---|
| `src/engine/abi.ts` | Constants and enums mirrored from `include/ccsim/wasm/ccsim_api.h` |
| `src/engine/config.ts` | Configuration model, 19-word encoding, geometry, live validation (mirrors `Hierarchy::check`) |
| `src/engine/events.ts` | Decoder for the binary event buffer (20 header words + 5 per action) |
| `src/engine/protocol.ts` | Main thread ↔ worker messages (ARCHITECTURE 8.2) |
| `src/engine/worker.ts`, `client.ts` | The worker that owns the WASM module, and its promise-based client |
| `src/engine/trace.ts` | Streams a trace (text, file or URL; gzip detected by magic bytes) into the worker in 1 MiB chunks |
| `src/engine/report.ts` | Types for `ccsim.simulation/1` and `ccsim.comparison/1` |
| `src/store/useApp.ts` | The single store: config, active run, position, grids, report, comparison entries, the live race, the one-shot autoplay flag, and the reset for a completely new run |
| `src/router.ts` | Hash routes: `#/` Home, `#/learn`, then the flow `#/simulate` → `#/visualize` → `#/analytics` → `#/compare` |
| `src/pages/` | Home (introduction and how to run), Learn (cache memory in depth), Configure, Visualize, Analytics, Compare (set-up and results), Race (configurations live side by side) |
| `src/components/` | Top bar with the gated next step, the sorting case (cache sets as cubbies), postmarks, recording replay, config form, trace picker, chart panel, icons |
| `src/recordings.ts` | Engine recordings of the example traces that Home and Learn replay without WebAssembly |
| `src/examples.ts` | The sample trace offered on Configure and Compare, and the example traces Learn offers for download (bodies from `tests/data`, comments rewritten for readers) |
| `src/lib/` | Formatting (`null` → "n/a"), theme palette, chart chrome, narration, chart data shaping, comparison checks, exports (PDF, CSV, JSON), engine check of an uploaded trace, playback speeds, the cache hierarchies offered on Configure |
| `src/assets/`, `public/favicon-*.png`, `public/apple-touch-icon.png` | The logo (top bar, footer) and favicons, cut from `logo.png` at the repository root |
| `src/styles/app.css` | The whole stylesheet: light and dark tokens, the sorting-office components, motion, print layout for PDF |
| `test/` | Vitest suites and engine-generated fixtures |
| `public/_headers` | Cloudflare Pages headers: CSP, `application/wasm`, immutable hashed assets |

## Setup

Node ≥ 22.12 (Vite 8). From `web/`:

```bash
npm ci
npm run typecheck
npm test            # Vitest: decoder, config encoding, visualiser, analytics, CSV export, comparison checks
npm run build       # tsc + vite build into dist/
npm run dev         # dev server
```

## The engine module

The site loads `engine/ccsim.mjs` (and its `ccsim.wasm`) relative to the page. Build it with
Emscripten from the repository root, then copy it into `public/engine/` (git-ignored):

```bash
emcmake cmake -S . -B build-wasm -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build-wasm --target ccsim_wasm
cd web && npm run wasm:copy          # or: npm run wasm:copy -- <other-build-dir>
```

Without it the UI loads, but starting a run reports that the engine module is missing. CI builds
the module in the `wasm` job and the site around it in the `web` job (artifact `ccsim-site`).

## Fixtures

`test/fixtures/` holds engine output for Demos A–C and their write-policy and inclusion variants:
config words, raw event words, `ccsim.events/1` JSON, grid snapshots after every access, reports
and comparisons. They are generated by `tests/tools/web_fixtures.cpp` through the same C ABI the
worker uses, and ctest checks they are current (`unit.web_fixtures_current`). After an engine
change that alters them, regenerate from the repository root:

```bash
cmake --build build --target ccsim_web_fixtures
./build/tests/ccsim_web_fixtures --write web/test/fixtures
```

Hand-derived values (Demo B latencies and AMAT from [WORKING_DEMO](../docs/WORKING_DEMO.md)) are
asserted separately in the tests, so the fixtures are not the only oracle.

## Flow

A run starts only from an uploaded trace. The engine reads the file the moment it is chosen and either
accepts it (access count and fingerprint) or rejects it with the first malformed line; Run stays disabled
until it is accepted. Configure unlocks Visualize once a run starts. Analytics unlocks when the run reaches its last access
(playing, seeking or **Finish run**), and Compare unlocks once the full report has loaded. The next step
is the button at the top right. Compare has three pages: set-up with the fairness checks, the race (up to
four configurations stepping in lockstep, each an engine session in one worker, with the engine's report so
far as a scoreboard), and the results, which open when every watched run reaches the end. Analytics and
comparison results export as PDF (the browser's print
dialog with the print stylesheet), CSV (every table; an unavailable value is an empty cell) and the
engine's JSON.
